# Sker GitHub Action

Use this composite action after checking out the PR merge ref with full history and making the `sker` executable available on `PATH` (or set `sker-path`). The action invokes exactly:

```text
sker check --ci --sarif <path> --json <path>
```

The containing workflow must grant the permissions it needs; composite actions cannot elevate workflow permissions:

```yaml
permissions:
  contents: read
  pull-requests: write # idempotent compliance matrix comment
  issues: write        # issue-comment API used for PR comments
  security-events: write # SARIF upload
```

Configure the `protected-agent-label` as a label whose assignment is restricted by repository policy. An existing credential file is Agent evidence even when the PR declares `Sker-Actor: human-only`. Agent credential verification compares its bundle and diff bindings with the fresh CheckReport generated by this run, validates semantic declarations, and verifies the RFC 8785-style canonical JSON BLAKE3 digest. The action does not create or modify credentials. A human exit code 2 is fail-open; an Agent exit code 1 or 2 blocks. Deterministic exit code 1 blocks for either actor.

Optional Ledger ingestion requires `ledger-url`; `ledger-token` is optional for deployments configured without bearer auth. The payload is limited to event ID/time, bundle digest, changed-line count, event type, and allowlisted aggregate labels. Posting is asynchronous and fail-open.
